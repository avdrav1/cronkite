# Etch

Fast, lightweight Linux-native raster image editor (user decision). Command `etch`. Etch sits where MacPaint, Microsoft Paint, and the simple end of Paint.NET sit, not beside GIMP, Photoshop, or Krita: "I just need to edit this image." Design: [ADR 0010](../adr/0010-etch-image-model.md) (image model, history, canvas).

## Principles

- **Simple.** Someone who launches Etch understands it at once: a menu bar, a tool column, the canvas, a colour row, and a status bar. No docks, no panel collections, plain words over graphics jargon.
- **Fast.** It starts quickly, opens ordinary images quickly, and drawing, zooming, panning, and changing tools respond at once. Interaction latency matters more than huge professional files: images up to 8K (7680×4320) stay practical.
- **Familiar.** The tools of a Paint program, where Paint users expect them: pencil, brush, eraser, fill, colour picker, line, rectangle, ellipse, text, selection, crop, zoom.
- **Native Linux.** GTK 4 like the rest of the suite (ADR 0002); developed on Arch, released for Arch, Ubuntu 24.04, and Fedora.

├───────┴──────────────────────────────────────┤
│ Colors                       100%   1024×768 │
└──────────────────────────────────────────────┘

The canvas takes the window; permanent UI stays small. Menus appear as their commands arrive: there is no empty Image or Tools menu.

## Image model

One RGBA8 raster per document (straight alpha), whatever the file format: JPEG's lack of alpha never shapes the model; conversion happens when exporting. No layers in V0.1, but nothing in the document rules them out (ADR 0010). No native `.etch` format until Etch keeps something PNG can't (layers, editable text or shapes); PNG, JPEG, and BMP files are the documents.

## Files

- New, Open, Save, Save As, Export, Close, and recent files. PNG, JPEG, and BMP; WebP if the codec comes for free. New images save as PNG by default.
- Installing Etch makes it the default app for PNG, JPEG, and BMP, so double-clicking an image opens it in Etch (user decision); uninstalling gives the types back.
- **New Image** asks for width and height in pixels (remembered from the last new image) and a background: white, transparent, or the current background colour. Presets (1920×1080, 1280×720, 1024×1024) may come later.
- Unsaved changes are tracked; closing an edited image asks Save, Discard, or Cancel. Work is never silently dropped. Saving is atomic through `suite-file`; unsaved changes are journaled for crash recovery (ET3).

## Canvas

Zoom in, zoom out, fit to window, actual size, pan, the image centred when smaller than the window, a visible image boundary, and a checkerboard behind transparency. Zoom runs from 10% to 3200% and keeps the point under the pointer (or the window's centre, from the keyboard) fixed. At 100% and above pixels show as sharp squares (nearest neighbour); below, the image is smoothed. The image is drawn in the screen's own pixels, at any display scale and with any of GTK's renderers (GL, Vulkan, or the software one): every edge of the image, of its 256-pixel tiles, and of the checkerboard's squares falls on a screen pixel's edge, so the tiles meet without a seam, a one-colour image shows that colour and nothing else at every zoom, and the checkerboard's squares are crisp up to the image's edge.

## Tools

- **Pencil:** hard-edged, one colour, a size.
- **Brush:** freehand with a size and a hard or soft edge; not a brush engine.
- **Eraser:** erases to transparency (the model is always RGBA).
- **Fill:** floods the contiguous region of the clicked colour with the foreground, taking colours within a tolerance of it (exact at first).
- **Colour picker:** a click sets the foreground colour from the image.
- **Line, Rectangle, Ellipse:** line width and colour; rectangles and ellipses outlined, filled, or both, previewed while dragged.
- **Text:** text, font family, size, colour, bold, italic; rasterized when committed. Editable text objects may come later; nothing in V0.1 depends on them.
- **Selection:** rectangular; drag to select, move the selected pixels, cut, copy, paste, delete, select all, deselect.

## Colours

A foreground and a background colour, a compact palette of familiar colours, a custom colour chooser, and hex entry. No colour management.

## Selection, clipboard, and image commands

- Pasted pixels float, movable, until committed. Copy puts the selection on the Linux clipboard as an image other apps can paste; paste takes images (screenshots) from other apps.
- **Crop to Selection** (Image menu): the canvas becomes the selection's bounds.
- **Resize Image:** width, height, keep aspect ratio; nearest neighbour or smooth.
- **Resize Canvas:** width, height, and an anchor of nine (↖ ↑ ↗ ← ● → ↙ ↓ ↘); new area transparent or the background colour.
- **Rotate** 90° either way and 180°; **Flip** horizontally and vertically. Arbitrary angles later.

## Undo

Every change undoes and redoes: strokes, erasing, fills, shapes, text, crop, resize, moving a selection, paste, delete, rotate, flip. History stores each step's operation and the pixels it replaced, never a copy of the whole image per stroke (ADR 0010).

Tool keys and X work only while no text is being typed (the size field included). No key is bound twice.

On macOS, Command replaces Ctrl in every shortcut, Ctrl+wheel and Ctrl+Home and Ctrl+End in text included (⌘S, ⇧⌘S, ⌘+, ⌘-wheel), and the menus show them so (MAC-3). Redo is ⇧⌘Z (Ctrl+Y is Linux's alone), and Rotate 90° Right is ⌘] (Pixelmator's), as ⌘H hides the app; nothing stays on Control.

On macOS the menu bar is the system's (MAC-4): the app menu (About Etch, Update Automatically, Services, Hide, Quit ⌘Q), then File, Edit, View, and Image, and Window (Minimize ⌘M, Zoom, the windows). File has no Quit there, as the app menu has it. Windows keep macOS's title bar.

On Windows (WIN-3) each window has Windows' own title bar (minimize, maximize, close, snapping) and the menu bar under it, as on Linux, with Help (Update Automatically, About Etch) after Image; File ends with Exit instead of Quit. Etch is a GUI program there, so no console window opens with it, and `etch --version` still prints in the terminal it was started from (after the next prompt) or into a file or pipe. It follows Windows' app mode, light or dark, the title bar too, also when it changes while Etch runs. Shortcuts stay Control.

## Status bar

Pointer position in image pixels, the selection's size, zoom, and the image size: `x: 342  y: 191      Selection: 320×180      100%      1920×1080`.

## Milestones

The phases of the product plan, one milestone each (`BACKLOG.md`, chain `etch`):

- **ET0, canvas prototype:** window, canvas, New Image, zoom, pan, pencil, eraser, colours, undo and redo; drawing feels immediate and navigation smooth. Desktop entry and installer, so a release can ship.
- **ET1, a Paint replacement:** opening and saving PNG, JPEG, and BMP, brush, fill, colour picker, line, rectangle, ellipse, text.
- **ET2, image manipulation:** rectangular selection and moving it, cut, copy, and paste through the clipboard, crop, resize image, resize canvas, rotate, flip. ET2's gate is V0.1: a user can create or open an image, draw and erase, pick colours, draw shapes, add text, select and move regions, crop, resize, rotate or flip, copy and paste, undo, and save as a common format.
- **ET3, desktop polish:** drag and drop, recent files, a better colour chooser, every tool key, crash recovery, clearer errors.

## ET0: canvas prototype

Built (ETCH-2 to ETCH-5):

- **Window.** `etch` opens a window with a blank white 1024×768 image, titled Untitled ("Untitled 2" beside it, and so on), with a menu bar (File: New Image…, Close, Quit; Edit: Undo, Redo; View: Zoom In, Zoom Out, Actual Size, Fit to Window), the canvas, and a status bar (pointer position in image pixels, zoom, image size). Each image has its own window.
- **New Image.** Ctrl+N asks for a width and height (1 to 16384 pixels each; the last ones used, 1024×768 at first) and opens the image in a new window (its background since ETCH-13: see ET1).
- **Canvas.** The image sits centred on the window's backdrop with a one-pixel boundary, at 100%, or fitted with a margin when larger than the window. Ctrl+wheel zooms a step a notch around the pointer (a touchpad smoothly), Ctrl++ and Ctrl+- around the window's centre, through 10%, 12.5%, 16.7%, 25%, 33.3%, 50%, 66.7%, 100%, 150%, 200%, 300%, 400%, 600%, 800%, 1200%, 1600%, 2400%, 3200%; a zoom between steps (after Fit) goes to the next one. The wheel pans 48 screen pixels a notch (Shift+wheel sideways), and dragging with the middle button or with Space held moves the image with the pointer. The image can't be panned out of sight (16 pixels of it stay in); smaller than the window, it stays centred. Resizing the window keeps the point at its centre.
- **Drawing stays immediate.** The canvas redraws only the 256-pixel tiles a stroke changed. `etch --bench-stroke FRAMES` draws a stroke a segment a frame on a 7680×4320 image at 100% and prints its frame times: on a Ryzen 9 5900 under Hyprland, 1.2 ms p99 a frame (target 8 ms).
- **Tools.** A column at the window's left holds a button a tool, each with its icon and its name and key as the tooltip; one is on at a time, Pencil at first. A tool's key picks it too: P the pencil, E the eraser.
- **Colours and sizes.** Below the canvas, left of the status: the foreground colour's square over the background's (their hex values in its tooltip), the palette of Paint's 20 colours (a click makes one the foreground, a right-click the background; X swaps the two), and the current tool's Size, 1 to 100 pixels. Each tool keeps its own size: the pencil starts at 1, the eraser at 9. A tip a few screen pixels across or more shows as a ring around the pointer, where a drag would draw.
- **Pencil.** Dragging draws a line of the foreground colour at the pencil's size through every pixel the pointer crossed (a click draws one dot); each drag is one undo step.
- **Eraser.** Dragging erases a line at the eraser's size to transparency, whatever the image was; the canvas's checkerboard shows through. Each drag is one undo step.
- **Undo.** Ctrl+Z undoes the last stroke, Ctrl+Shift+Z and Ctrl+Y redo it; a new stroke after undoing drops what was undone.
- **Install.** A per-user curl installer, as the other apps have (`sites/etch/install.sh`: `curl -fsSL https://etch.cronkite.cc/install.sh | sh`, `| sh -s -- --uninstall`), with no sudo. It checks the release against its sha256 and puts `etch` in `~/.local/bin` and its menu entry and icon (`dev.cronkite.Etch`, the app ID) in `~/.local/share`. Since ETCH-6 it also makes Etch the default app for PNG, JPEG, and BMP (see ET1). GTK 4 comes from the system; without it, the installer says how to get it. The download page is `sites/etch/` (etch.cronkite.cc), and cronkite.cc lists Etch as an early preview.
- **Install on macOS (MAC-7).** Etch is `Etch.app` for Apple Silicon and macOS 14 or later, carrying GTK and everything it reads (no Homebrew), signed ad hoc. The same curl command puts it in `~/Applications` and registers it with Launch Services, so PNG, JPEG, and BMP images list it under Open With; it doesn't change the Mac's default apps (Finder's Get Info, Open with, Change All does), and `--uninstall` removes it and its registration. The download page also offers a DMG, with Gatekeeper's Open Anyway steps.

## ET1: a Paint replacement

Built so far (ETCH-6 to ETCH-14):

- **Opening.** `etch FILE...` opens each image in a window of its own, titled with the file's name; File → Open… (Ctrl+O) picks one through the desktop's file dialog, filtered to images (PNG, JPEG, BMP; All files is the other filter). Open always opens a new window, as in Slate and Frame: an Untitled window stays as it is. A file already open brings its window forward. The file is read and decoded off the UI thread while its window says "Opening…", so other windows stay usable; then the image shows at 100%, or fitted when it's larger than the window.
- **Formats.** PNG, JPEG, and BMP, told by the file's content, not its name: a GIF named `.png` is a GIF. Images decode to the one RGBA8 raster. PNG keeps its alpha, fully transparent pixels included (their colour too). JPEG has none, and every BMP opens opaque: the fourth byte of a 32-bit BMP is unused in most files, so Etch reads it as Paint does. Images over 16384 pixels a side are refused before their pixels are decoded.
- **When a file can't be opened,** an alert names it and says why, and its window closes: "Cannot open “photo.png”" over "It's a damaged or incomplete PNG image (the file ends too soon).", "It's a GIF image. Etch opens PNG, JPEG, and BMP images.", "It isn't an image Etch can open: PNG, JPEG, or BMP.", "The file is empty.", "The file doesn't exist.", "You don't have permission to read it.", or "It's 20000×100 pixels; Etch opens images up to 16384 pixels a side." A JPEG missing its end (cut short) counts as damaged rather than opening grey at the bottom.
- **Fast.** An 8K PNG (7680×4320) shows within a second: `etch --bench-open FILE` prints the time from start to the first frame that drew the image.
- **The default app for images.** The installer makes Etch the default for PNG, JPEG, and BMP in `~/.config/mimeapps.list` (user decision), replacing another app's default for them, so double-clicking an image opens it in Etch; every other type's default stays. Uninstalling drops Etch's defaults (the types go back to whatever the desktop picks).
- **Saving.** File → Save (Ctrl+S) writes the image over its file, in the format the file was opened in; an image never saved asks where first, as Save As does, offering Untitled.png (Untitled 2.png, and so on) in the Pictures folder. File → Save As… (Ctrl+Shift+S) asks for a file through the desktop's file dialog, filtered to PNG, JPEG, or BMP images (the image's own format first); the name's extension picks the format (.png; .jpg or .jpeg; .bmp, in any case), and the file becomes the window's: its title, what Save writes next, what opening it again brings forward. A name without one of those extensions alerts "Cannot save “drawing.gif”" over "Etch saves PNG (.png), JPEG (.jpg or .jpeg), and BMP (.bmp) images: end the name with one of them."
- **Export.** File → Export… (Ctrl+Shift+E) writes a copy the same way, in the format its extension picks, but the window keeps its own file, format, and unsaved changes: a JPEG for sharing while the PNG stays the document.
- **Formats written.** PNG keeps every pixel exactly, alpha included (and the colour of fully transparent pixels). JPEG (quality 90) and BMP (24-bit) can't be transparent, so their pixels are composited onto white; saving or exporting an image with any transparent or see-through pixel as either first asks "Save “photo.jpg” without transparency?" ("JPEG images can't be transparent: the image's transparent and see-through pixels become white in the file."), Cancel or Save. The window keeps its transparency after such a save.
- **Saving stays out of the way.** The image is copied when the save begins (18 ms for 8K on a Ryzen 9 5900), then encoded and written off the UI thread, so drawing goes on meanwhile; the file holds the image as it was when the save began. A save asked for while another runs waits for it. Writing is atomic through `suite-file`: a temp file beside the file, read back and compared, synced, then renamed over it, so a save that fails (a full disk, a folder without write permission) leaves the old file whole and alerts "Cannot save “photo.png”" with the reason ("You don't have permission to write there.").
- **Unsaved changes.** The window's title starts with "• " while the image differs from its file (or, never saved, from the blank it started as). It's the history that counts: undoing back to the image saved clears the mark, redoing sets it again. Closing such a window (its close button, File → Close, Ctrl+W) or quitting (Ctrl+Q asks in each window) asks "Save changes to “photo.png” before closing?" with Cancel, Discard, and Save: Cancel keeps the window, Discard closes it leaving the file as it was, Save saves (asking where for a new image) and then closes; a save that fails or is cancelled keeps the window open.
- **Brush.** The tool column's Brush (B) draws the foreground colour in a round tip, 8 pixels at first (its own size, as each tool keeps), with a hard or a soft edge: Hard and Soft show beside the size while the brush is the tool, Soft at first. A hard edge is solid to the rim; a soft one fades smoothly from the full colour at the centre to nothing at the rim. The brush blends over what's there (a see-through colour lets the image show through) rather than replacing it as the pencil does. Within one drag the paint never builds up: going back and forth slowly over the same pixels looks the same as one quick pass, so a slow soft stroke doesn't turn solid; a second drag over the first does blend over it. Each drag is one undo step.
- **Fill.** The tool column's Fill (F) fills the region the clicked pixel belongs to with the foreground colour, a right-click with the background (as in Paint): every pixel of the clicked colour, or within the tolerance of it, reachable from it through pixels' edges (not their corners). Tolerance, beside the colours while the fill is the tool (in place of the size, which the fill hasn't got), is how far a colour may be from the clicked one, 0 to 255: a pixel fills when none of its channels, alpha included, differs from the clicked pixel's by more (the largest difference, as GIMP's threshold, not a sum or a percentage). At 0, the default, only the exact colour fills, so a line one pixel wide, of any other colour however close, stops it; at 6 a colour six levels off in one channel fills and seven doesn't; at 255 everything reachable fills. A fully transparent pixel's colour can't be seen, so with one only alpha counts: fully transparent pixels are one colour whatever colour they hide (a transparent area fills whole), and at 5 they take pixels of any colour up to alpha 5. The tolerance is kept while other tools are used. The fill replaces pixels rather than blending. Each fill is one undo step, and history keeps only the 64-pixel tiles it changed. Filling all of an 8K image takes about 80 ms on a Ryzen 9 5900 (under 200 ms at worst), so the fill lands at once rather than in the background.
- **Colour picker.** The tool column's Colour Picker (I) makes the colour of the clicked pixel the foreground, a right-click the background, alpha included: a see-through pixel gives a see-through colour, and a fully transparent one a fully transparent colour. Then it goes back to the tool used before it, as Paint's does, so picking a colour and painting with it is I, a click, and a drag. Picking changes no pixel and no history. It has no size. The colour row shows a see-through colour over a checkerboard, and its tooltip and accessible description give it as `#RRGGBBAA` (`#RRGGBB` when opaque).
- **Line, Rectangle, and Ellipse.** The tool column's Line (L), Rectangle (R), and Ellipse (O) draw shapes by dragging: from the pixel pressed to the pixel under the pointer, a line between them, or the rectangle or ellipse filling the box they span. While the drag goes on the shape shows on the canvas over the image, exactly as it will land, but the image isn't touched (the title stays unmarked); the release draws it as one undo step, and Escape before the release drops it. Shift keeps a line to the nearest 45° and a box square, so a circle. Each has its own size, the outline's width (1 at first). Shapes are hard-edged like the pencil, not smoothed: a line is the pencil's line at that width; a rectangle's outline runs inside its box with square corners; an ellipse touches its box's four sides, its outline inside it too. Rectangles and ellipses are Outline, Filled, or Both, chosen beside the size while either is the tool (one choice for the two, as in Paint), Outline at first: the outline is the foreground colour, Both fills inside it with the background, and Filled is the whole shape in the foreground with no outline (as in Paint and Paint.NET). A see-through colour lays one coat over the image, as the brush does. History keeps only the 64-pixel tiles a shape changed, so an outline round a large image keeps its edge's tiles, not its middle.
- **Text.** The tool column's Text (T) types text onto the image. A click on the image starts text there, its top-left corner at the pixel clicked, in a dashed frame with a caret (a click off the image starts none). Typing goes through the desktop's input method, so any script composes, the composition showing underlined until it's committed. Shift+Enter starts a new line; Backspace and Delete delete a character; the arrows, Home, and End move the caret (Ctrl+Home and Ctrl+End to the text's ends), and a click inside the frame puts it there. While text is typed every key is the text's: P, E, X, Space, and the other tool keys type their letters rather than switching tools. The text shows on the canvas exactly as it will land, antialiased, in the foreground colour (alpha included) and the font set beside the size while text is the tool: a font family list (every family installed, Sans at first; typing into the opened list searches it), Bold, Italic, and the size, the font's em in image pixels (24 at first, 4 to 400). Changing any of them, or the colour, changes the text being typed. Typing doesn't touch the image: the title stays unmarked. Enter puts the text on the image as pixels, one undo step, and so does a click elsewhere on the canvas (which starts no new text), choosing another tool, saving, or closing the window; text without ink (spaces) changes nothing. Escape drops it, as does Ctrl+Z while typing (the next Ctrl+Z undoes the step before); Ctrl+Y does nothing while typing. Once on the image text is pixels like any other: it can't be edited as text again.
- **New Image's background.** New Image's dialog offers a background below the size: White (at first), Transparent, or Background colour, the background colour of the window it was asked from (its hex value in the tooltip; white with no window). A transparent image is every pixel alpha 0: the checkerboard shows through all of it, and saved as PNG it stays transparent. The size and the background last used are remembered across runs in `~/.config/etch/settings` (`$XDG_CONFIG_HOME/etch/settings`, `key=value` lines, written atomically off the UI thread). `etch` without a file still opens a white 1024×768 image: what's remembered is New Image's.

## ET2: image manipulation

Built (ETCH-15 to ETCH-20):

- **Selection.** The tool column's Selection (S) selects a rectangle by dragging: the pixels between the pixel edges nearest the press and the release (a drag across 200 pixels selects 200), clipped to the image. Its outline is dashed, black on white, so it shows on any colour, and the status bar says its size between the pointer position and the zoom: `Selection: 320×180`. A click outside it (or a drag selecting nothing) leaves no selection. Over the selection the pointer is a move cursor.
- **Moving the selected pixels.** A drag inside the selection lifts its pixels and moves them with the pointer: they float over the image, which isn't touched until they land (the title stays unmarked), and the place they left shows transparency (the checkerboard), as the model is always RGBA, not the background colour. More drags move them further. They land, replacing the pixels under them (see-through and transparent ones too, as they were), clipped to the image, when the selection goes: Escape, a click or drag outside it, choosing another tool, Select All, or saving or closing (which land them and keep the selection where they landed). Lifting, every drag, and landing are one undo step; Ctrl+Z while they float drops the move and the selection goes back where they were. The arrow keys move the selection's pixels a pixel (Shift: ten), lifting them as a drag does.
- **Edit menu.** Select All (Ctrl+A) picks the selection tool, as Paint does, and selects the whole image; Deselect (Escape) and Delete (Delete) work while there's a selection. Delete clears the selection's pixels to transparency, one undo step, and the selection stays; floating pixels are dropped instead, the place they were lifted from left transparent. While text is typed, or a field has the keys, Ctrl+A, Escape, Delete, and the arrows are theirs.
- **Fast enough on the UI thread.** Lifting a whole 8K image takes 26 ms, lifting and landing it 125 ms at worst, and deleting it 34 ms (Ryzen 9 5900; target 200 ms, as the fill's).
- **Clipboard.** Edit → Cut (Ctrl+X), Copy (Ctrl+C), and Paste (Ctrl+V). Copy puts the selection's pixels (the floating ones while they float) on the desktop's clipboard as an image, straight alpha, transparency included: other apps paste it as PNG or any other image type GTK writes. Cut copies, then deletes as Delete does, one undo step. Paste takes an image another app copied (a screenshot, a picture from a browser), converted off the UI thread, picks the selection tool, as Paint does, and floats the image over the canvas with its top-left pixel at the top-left of the visible part of the image (the image's own top-left when that shows): the status shows its size and the title stays unmarked. It moves, nudges, lands, and drops as moved pixels do, replacing the pixels under it when it lands, one undo step; Ctrl+Z while it floats drops it. An image larger than the canvas floats whole and lands clipped (Paint offers to enlarge the canvas; Etch doesn't yet); one over 16384 pixels a side keeps its top-left 16384. Nothing happens when the clipboard holds no image. While text is typed, or a field has the keys, Ctrl+X, Ctrl+C, and Ctrl+V are theirs: they never cut or paste pixels then. What Etch copies stays on the clipboard while Etch runs.
- **Image menu.** After View, holding the commands that change the whole image, its size too, in four groups: crop; resize image and canvas; rotate; flip. Each is one undo step whose undo gives back the image as it was, size and every pixel, and whose redo gives back the result. For the commands that lose pixels (crop and the resizes) history keeps the whole image on the step's other side, so undo and redo are instant whatever the image's size (ADR 0010); rotating and flipping lose none, so history keeps nothing for them: undo turns the other way or flips back, and redo turns or flips again (20 to 27 ms for 8K, on the UI thread). The command runs off the UI thread on a copy of the image (16 ms for 8K on a Ryzen 9 5900), the canvas not taking input until it's done; then the image shows anew with no selection, and the status gives its size: when the size changed, as an opened image shows (at 100% centred, or fitted when larger than the window), else in the same view. Text being typed and floating pixels go on the image first, each its own step.
- **Crop to Selection** (Ctrl+Shift+X): the image becomes the selection's pixels, its top-left pixel the selection's. Floating pixels land first and the crop takes the selection where they landed (clipped to the image). Without a selection the command is greyed out. Cropping an 8K image takes 22 ms.
- **Resize Image…** (Ctrl+R) asks for the new Width and Height in pixels (1 to 16384, the image's own at first), Keep aspect ratio (on at first: changing one side sets the other to keep the image's proportions, rounded), and the resampling: **Smooth** (at first) or **Nearest neighbour**. Nearest neighbour makes each new pixel the old pixel its centre falls in: no new colours, so doubling turns each pixel into a 2×2 square, as pixel art wants. Smooth averages the old pixels around each new one with a triangle filter (bilinear when enlarging; when shrinking, as wide as the shrink, so every old pixel counts), each colour weighted by its alpha, so the colour hidden in a transparent pixel never tints its neighbours; it gives what ImageMagick's `-filter Triangle -resize` gives, within a level. Resizing an 8K image runs off the UI thread: to 4K smooth 45 ms, to 15360×8640 smooth 295 ms (nearest 7 and 62 ms) on a Ryzen 9 5900's cores.
- **Resize Canvas…** (Ctrl+Shift+R) asks for the canvas's new Width and Height (1 to 16384, the image's own at first), the anchor, where the image stays on it: nine toggle buttons in a 3×3 grid (↖ ↑ ↗ ← ● → ↙ ↓ ↘, named Top left to Bottom right for screen readers, the centre on at first), and what fills the new area: Transparent (at first) or Background colour (the window's, its hex value in the tooltip). The image's pixels aren't scaled: a larger canvas adds the new area around them as the anchor says, and a smaller one crops them as it says. Centred, a pixel left over goes to the right and bottom: 5 more pixels across adds 2 on the left and 3 on the right, 3 fewer takes 1 off the left and 2 off the right. 8K to 8000×5000 takes 32 ms off the UI thread.
- **Rotate 90° Right** (Ctrl+H), **Rotate 90° Left** (Ctrl+G), and **Rotate 180°** (Ctrl+J) turn the image, a quarter turn swapping its width and height; **Flip Horizontal** and **Flip Vertical** mirror it left to right and top to bottom. Every pixel moves whole, nothing resampled: four quarter turns, two half turns, or two flips give back the image byte for byte. A quarter turn of an 8K image takes 24 ms off the UI thread, a half turn or a flip 19.

## ET3: desktop polish

Built so far (ETCH-21 to ETCH-25):

- **Drag and drop.** Image files dropped on any Etch window (from a file manager) open as Open opens them, each in a window of its own: several files open several windows, a file already open brings its window forward instead, and a file that isn't an image Etch can open alerts with its name and the reason, as opening it would.
- **Recent files.** File → Open Recent lists the last ten images opened or saved (Save and Save As, not Export), newest first, each by its name and its folder (`photo.png  (~/Pictures)`), across runs and across Etch windows and processes: the list is kept in `~/.local/state/etch/recent` (`$XDG_STATE_HOME/etch/recent`), one path a line, written atomically off the UI thread, and read again whenever a window becomes active. An image opened again moves to the top, once. Choosing one opens it as Open does; one that can't be opened any more (deleted, moved, damaged) alerts with the reason and leaves the list. With none, the submenu says "No recent images".
- **Hex entry and the colour chooser.** Beside the colours, the Hex field (Alt+H) shows the foreground colour as `#RRGGBB` (`#RRGGBBAA` when see-through); typing `#RGB`, `#RRGGBB`, or `#RRGGBBAA` (any case, the `#` optional) and Enter sets the foreground and gives the keys back to the image. Anything else is refused: the field turns red and is marked invalid for screen readers, and the colour stays; leaving the field shows the colour again (switching to another window keeps what's typed). While the field has the keys, tool keys and X are its letters. **Custom…** opens GTK's colour chooser with alpha for the foreground, a right-click on it for the background, as the palette's clicks do; its colour, alpha included, becomes the one chosen, and Cancel changes nothing.
- **Every tool on its key.** On the image each tool's key picks it: P the pencil, B the brush, E the eraser, F the fill, I the colour picker, T text, R the rectangle, L the line, S the selection, O the ellipse; X swaps the colours. While text is typed on the canvas, or a field has the keys (the size, the tolerance, the hex field, the font list's search), they are letters, and in an open menu a letter picks the menu's item (View's F fits the image to the window). Every key Etch binds is in one table: the tool keys, the menus' shortcuts (shown beside their commands), the selection's keys, Space, and the Alt mnemonics of the menu bar (Alt+F, E, V, I) and the colour row (Alt+H the hex field, Alt+S the size, Alt+T the tolerance); no combination is bound twice, a modifier making a different one (X swaps, Ctrl+X cuts, Ctrl+Shift+X crops). With a field holding the keys, Ctrl+Shift+X and Ctrl+Shift+R crop and resize the canvas as Ctrl+Shift+S and Ctrl+Shift+E save as and export; Shift+Escape drops a shape being dragged with Shift held.
- **Crash recovery.** A window with unsaved changes keeps a journal of its image in `~/.local/state/etch/recovery` (`$XDG_STATE_HOME/etch/recovery`, through `suite-file`'s recovery store): written 5 seconds after the first change not yet in it, so at most every 5 seconds while drawing goes on, off the UI thread, atomically. It holds the image's file (its path, size, and modification time when read or last saved), the time, and the image itself as a PNG. Saving, undoing back to the file, and closing the window (saved or discarded) remove it, so a journal left after Etch has gone means a crash or a kill. Opening such a file afterwards (from the command line, Open, Open Recent, or a drop) asks "Restore unsaved edits?" (Discard, Restore); `etch` started without files opens each crashed image in its own window instead of a blank one, its file as it is now or, for an image never saved, a new white Untitled image of its size, and asks the same. Restore puts the journal's pixels in place of the file's as one undoable step, size and all: the title shows "• ", the file stays as it was until saved, and one Ctrl+Z gives back the file's pixels. Closing the question without an answer offers it again next time. If the file changed after the crash (its size or time), or can't be opened, the pixels aren't put onto it: "“photo.png” changed after the crash" offers Keep for Later and Discard.
- **Folders on macOS (MAC-2).** The settings, the recent list, and recovery journals live in `~/Library/Application Support/dev.cronkite.Etch` (`settings`, `recent`, `recovery/`) instead of `~/.config/etch` and `~/.local/state/etch`; Linux keeps its XDG folders.
- **Folders on Windows (WIN-2).** The settings and the recent list live in `%APPDATA%\Cronkite\Etch` (`settings`, `recent`), which roams with the user's profile, and recovery journals in `%LOCALAPPDATA%\Cronkite\Etch\recovery`. Open Recent shows each image's folder in full there (`photo.png  (C:\Users\me\Pictures)`), not with `~`. Crash recovery works as on Linux: an Etch that's killed leaves its journal, which the next Etch offers back, and another running Etch's journals are left alone.
- **Fonts and appearance on macOS (MAC-6).** Text draws through fontconfig as on Linux, over the Mac's own fonts, so the text tool's font list is fontconfig's. The window follows the Mac's light or dark appearance, also when it changes while Etch runs.
- **Opening from Finder on macOS (MAC-5).** Finder's Open and Open With, an image dropped on Etch's Dock icon, and `open -a Etch` open each image in a window of its own in the running Etch (Launch Services keeps one Etch, and GTK hands it the files); an image already open brings its window forward. Started without a file it opens the blank image (or a crash's images), and started for an image only that image's window, no Untitled one beside it. On Linux each `etch FILE…` is its own process, as before. Etch draws with cairo on macOS unless `GSK_RENDERER` names another renderer: GTK's GL renderer drew black windows on GitHub's macOS runners and is untried on a real Mac. On the runner cairo draws the 8K stroke benchmark's frames in 1.2 ms (p50) and 5.2 ms (p99).
- **Fonts and opening on Windows (WIN-4).** Text draws through fontconfig, over Windows' own fonts, so the text tool's font list is fontconfig's. An image on the command line, from Explorer's Open with, or by a registered type opens in an Etch process of its own, as on Linux; an image dragged from Explorer onto a window opens. GTK chooses the renderer (cairo without a GPU).
- **Installing on Windows (WIN-5).** Etch installs for the user alone, without admin rights, from its Setup.exe or `irm https://etch.cronkite.cc/install.ps1 | iex`, into `%LOCALAPPDATA%\Programs\Etch` with GTK inside and a Start menu entry. PNG, JPEG, and BMP images (`.png .jpg .jpeg .bmp`) list it under Open with and in Settings → Default apps; Windows keeps the user's defaults. Settings → Apps uninstalls it; the settings, recent list, and recovery journals in `%APPDATA%\Cronkite\Etch` and `%LOCALAPPDATA%\Cronkite\Etch` stay (uninstalling by hand asks whether to remove them too).
- **Download page on Windows (WIN-6).** etch.cronkite.cc offers a Windows visitor the Setup.exe on its button, the PowerShell command first under Install, and, for a Setup.exe downloaded in a browser, SmartScreen's way past "Windows protected your PC" (More info → Run anyway); Linux and Mac visitors keep theirs first, and every platform's download stays listed.
- **Updates (UPD-3).** Etch updates itself (ADR 0012): an install from the installer checks its release folder once each start, off the UI thread, downloads a newer release in the background when its Ed25519 signature and sha256 verify, and runs it from the next start (UPD-2 to UPD-6). "Update Automatically" turns it off (UPD-3): a check item in the menu bar's Help (with About Etch) on Linux, after About Etch in the Etch menu on macOS, and in Help on Windows; on by default, kept in the settings folder's `update` file. `CRONKITE_NO_UPDATE=1` turns it off for one run; off, Etch makes no network request. The first start of a version an update applied says "Updated to Etch X.Y.Z" once, in a banner over the top of its first window that never takes the keys and goes when dismissed or after 20 seconds.

## Non-goals for V0.1

Layers, masks, vector illustration, advanced brushes, PSD, CMYK, RAW, colour management, adjustment layers, advanced filters, animation, professional typography, plugins, AI generation, collaboration. Later candidates, once the basics are strong: layers, editable text and shapes, blur, sharpen, greyscale, brightness and contrast, hue and saturation, selection shapes, magic wand, arbitrary rotation, guides, rulers, a pixel grid, SVG import as raster, and `.etch`.
